1. Where in the existing code does it plug in?

In src/pipeline/anpr_pipeline.py, right inside the process_frame() loop where vehicles are already detected:

# Inside ANPRPipeline.process_frame(): for track in tracked_vehicles: if track.cls_name in ['motorcycle', 'scooter']: # 🚀 NEW HOOK: Invoke Triple Riding & Helmet Detector violation_res = self.triple_riding_detector.analyze_motorcycle( frame=frame, bike_bbox=track.bbox, persons=detected_persons ) if violation_res['is_violation']: # Save permanently & trigger WebSocket alert violation_db.record_violation(violation_res) self.broadcast_violation_alert(violation_res)

2. Database Isolation: Why violations will never disappear

The live camera monitor currently uses an in-memory queue/ring buffer (100 items).
The new data/violations.db is an independent SQLite database table. Every entry has a unique UUID, ISO-8601 timestamp, camera location, plate number, rider count, helmet status, and path to the evidence JPEG. It is never truncated or overwritten.

3. Zero-Breaking-Change Guarantee

• Existing ANPR Pipeline for cars, buses, and trucks runs without modification.
• Existing FRS (Face Recognition) pipeline is completely untouched.
• Existing Master DB & Search continues functioning normally.
• If the operator disables or ignores violations, the normal tracking stream operates as usual.
